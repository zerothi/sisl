`~sisl.SparseCSR` supports both ``int32`` and ``int64`` indices

The index arrays (``ptr``, ``ncol`` and ``col``) always share the same
integer data-type. It is chosen automatically from the matrix dimensions and
number of elements, so small matrices use ``int32``, while matrices
too large for ``int32`` use ``int64``. The index arrays are promoted to
``int64`` when the sparse pattern grows beyond the ``int32`` range.
A specific data-type can be requested with ``SparseCSR(..., idtype=np.int64)``.

Fixes :issue:`902`.
